# Гипотеза и план проверки

## 1. Формулировка гипотезы

> Если заменить независимое per-particle моделирование динамики на **иерархическую схему с rigid-body ограничениями на уровне семантически сгруппированных объектов**, где физические параметры вычисляются только для **репрезентативных гауссианов (centroids объектов)**, а движение остальных propagated через относительные трансформации, то:
>
> - **вычислительная сложность экстраполяции снизится с O(N) до O(K)**, где K — число семантических объектов (на 2–3 порядка меньше N);
> - **физическая правдоподобность траекторий сохранится**, поскольку rigid-body propagation сохраняет межточечные расстояния внутри объекта;
> - **появится возможность object-level семантического взаимодействия** (open-vocabulary queries, selective rendering) без дополнительного обучения;
> - **появится основа для temporal semantic consistency** за счёт привязки семантики к объектам, а не к частицам.

## 2. Обоснование

Гипотеза опирается на:

- **R5DGS** — демонстрирует, что rigid-body propagation на уровне объектов даёт +11 FPS относительно 5DGS при сохранении физической правдоподобности.
- **Обзор Gong et al.** — подтверждает, что проблема эффективности и масштабируемости открыта на уровне сообщества.
- **GSplatLoc** — показывает, что интеграция внешних дескрипторов (XFeat) в 3DGS работает; аналогично можно интегрировать семантические эмбеддинги.
- **Практическая часть данной работы** — эмпирически подтвердила, что baseline TRACE на consumer-GPU исчерпывает **вычислительные ресурсы** (не память) на фазе densification: скорость падает с 101 до 7 it/s при VRAM 60%.

## 3. Что нового в гипотезе

R5DGS работает при K < 40 объектов. Гипотеза предлагает **многоуровневую иерархическую группировку**:

- уровень 1: части → объекты (как в R5DGS);
- уровень 2: объекты → сцены/кластеры;
- уровень 3: кластеры → temporal-стабильные сущности.

Это должно снять ограничение K < 40 и обеспечить temporal semantic consistency.

## 4. План проверки

### 4.1. Baseline

- **TRACE** — физически-обоснованный 4DGS с per-particle динамикой.
- **R5DGS** — rigid-body на объектах, K < 40.

**Статус:** baseline TRACE воспроизведён (см. `results/training_log_chessboard.md` и `notebooks/practical_validation.ipynb`). R5DGS недоступен (код не опубликован), его метрики оценены аналитически.

### 4.2. Proposed modification

1. **Иерархическая группировка:**
   - уровень 1: Identity Encoding (как в R5DGS);
   - уровень 2: кластеризация объектов по spatial-temporal proximity;
   - уровень 3: temporal tracking объектов через Hungarian matching или аналоги.

2. **Многоуровневый rigid-body propagation:**
   - динамика вычисляется для centroids кластеров;
   - внутри кластера — propagated через относительные трансформации;
   - между кластерами — независимая динамика.

### 4.3. Метрики

| Категория | Метрика | Что показывает |
|---|---|---|
| Эффективность | FPS при экстраполяции | Скорость |
| Эффективность | Inference complexity | O(N) vs O(K) |
| Эффективность | GPU memory | Память |
| Качество | PSNR | Точность реконструкции |
| Качество | SSIM | Структурное сходство |
| Качество | LPIPS | Перцептивное качество |
| Семантика | mIoU | Качество группировки |
| Семантика | Temporal consistency | Стабильность меток во времени |
| Физика | Сохранение межточечных расстояний | Физическая правдоподобность |

### 4.4. Датасеты

- **Dynamic Indoor Scene** (Dining Table, Chessboard, Darkroom, Factory) — основной.
- **ScanNet200** — для проверки масштабируемости.
- **Replica** — для проверки качества семантической группировки.

### 4.5. Ожидаемый результат

- Подтверждение ускорения ~11 FPS относительно 5DGS при падении PSNR в пределах 4–7 дБ (по данным R5DGS: 28–31 дБ против 34.80 дБ у TRACE @40000).
- Снятие ограничения K < 40 за счёт иерархической группировки.
- Улучшение temporal semantic consistency по сравнению с R5DGS.

## 5. Ожидаемый вклад

Формализация и эмпирическая валидация принципа **«физическая динамика на уровне объектов, а не частиц»** как способа разрешения конфликта между физической согласованностью и вычислительной эффективностью в 4DGS.

## 6. Результаты практической части

1. Установлено окружение под RTX 5050 (sm_120): PyTorch 2.11 + CUDA 12.8, gcc-13.
2. Скомпилированы CUDA-ядра `diff_gaussian_rasterization` и `simple_knn` с патчами под sm_120.
3. Воспроизведён baseline TRACE на сцене `chessboard` (Dynamic Indoor Scene), полное обучение 40000 итераций за 1 ч 31 мин.
4. Зафиксировано падение скорости обучения **в 14 раз** на фазе densification (**101 → 7 it/s**).
5. Зафиксировано потребление VRAM: **пик 6.6 / 8.1 ГБ (82%)** на densification, **4.9 / 8.1 ГБ (60%)** на плато — узкое место вычислительное, не ёмкостное.
6. Замерены метрики качества на чекпоинте 40000: **PSNR 34.80 дБ, SSIM 0.9659, LPIPS 0.0328** на экстраполяции.
7. Замерен FPS: **18.26 на экстраполяции** (чистое значение, обучение завершено), 23.0 на интерполяции.
8. Построены графики скорости обучения, VRAM и FPS vs PSNR.

**Направления дальнейшей работы** (за рамками текущего задания): повторение на сцене `dining`, реализация proposed modification, тестирование на K > 40.
